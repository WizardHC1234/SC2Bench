# 动作与观测接口

固定规则由 `PromptParts` 渲染。`LLMAdapter` 把同一份模块、`AgentInput`、`ToolSpec` 和 `ToolResult` 转成模型文本。Environment 提供 `tool_specs()` 和 `begin_tool_turn()`。模型提示词仍为英文；本文档为中文，不规定打法。

## 动作格式

每个动作是一次 `call_tool`。查询和动作可以交错。`advance` 提交已经暂存的动作，并填写正数游戏秒。下面的数组只说明一次决策里可以包含哪些调用，不是 Agent 的返回值。

```json
[
  {"name": "build", "arguments": {"target": "barracks"}},
  {"name": "train", "arguments": {"target": "marine", "count": 8}},
  {"name": "advance", "arguments": {"seconds": 30}}
]
```

示例仅说明格式，不写入系统提示词。无需新动作时返回 `[{"name": "advance", "arguments": {"seconds": 5}}]`。

## 支持的动作

| 动作 | 字段和含义 |
| --- | --- |
| `build` | `target`；追加一个建筑、附件或建筑形态。选址或变形来源由底层决定。基地按扩张放置 |
| `train` | `target/count`；`count` 是至少再获得的目标单位数。底层负责训练、折跃、孵化、单位变异或融合。一次游戏批次可能多于请求，反馈同时给出请求数和实际数 |
| `research` | `target`；当前任务尚在等待、游戏中正在研究或升级已完成时，重复提交不新增；研究队列丢失且未完成时可重新请求 |
| `cancel` | 使用 `target_action/target` 调整同动作、同目标的任务队列；可用 `count` 从最新请求开始撤销指定数量，省略时撤销全部匹配的未启动工作 |
| `morph_townhall` | `target/to`；人族和虫族。`target` 是观测中的 `townhall_<n>`。神族没有这个动作 |
| `scan` | `target` 为 Zone；仅人族。底层用可用热点选点，不保证扫描全区 |
| `call_mule` | 无额外字段；仅人族。矿区由底层选择。与扫描、补给投送共用轨道指挥部能量 |
| `supply_drop` | 无额外字段；仅人族。平台选择一座已完成且未投送过的补给站。与扫描、矿骡共用轨道指挥部能量，并按当前版本增加补给上限 |
| `chrono_boost` | 无额外字段；仅神族。消耗一座就绪星灵枢纽的 50 能量，底层选择正在生产或研究的建筑。不会自动施放 |
| `inject_larva` | 无额外字段；仅虫族。消耗一只就绪女王的 25 能量，底层选择一座主基地。不会自动施放 |
| `spawn_creep_tumor` | 无额外字段；仅虫族。优先由能力就绪的成熟肿瘤免费续铺，否则消耗一只就绪女王的 25 能量，在可放置菌毯上朝敌方种一个瘤。不会自动施放 |
| `scout` | `route` 为有序 Zone 数组，或字符串 `"all"` |
| `dispatch_group` | `source/units/order/target`；从指定来源拆出兵力。清图使用 `order="attack", mode="clear"`，省略 `target` |
| `attack_group` | `group/target` 进攻指定区域；或 `group/mode="clear"` 持续清图，省略 `target`。保留编队 ID 和成员 |
| `defend_group` | `group/target`；把已有外派编队改为防守指定区域，不改变成员，也不新建编队 |
| `reinforce_group` | `source/destination/units`；在 `group_0` 和活动外派编队之间转移指定单位，不改变目标编队的当前命令 |
| `merge_groups` | `destination/sources`；把一个或多个活动编队的存活成员转入目标编队，目标编队保留 ID 和当前命令 |
| `retreat_group` | `group`；可选 `method`。省略 `method` 时按移动撤回，到家后归并。神族 `method` 为 `recall` 时只使用当前主基地星灵枢纽召回，半径外的成员继续移动撤回；枢纽死亡、未完成、能量不足或技能不可用时失败，编队保持原命令 |
| `advance` | 必填正数 `seconds`；推进指定游戏秒后返回下一次观测 |

生产和科技的目标、成本、前提与参考耗时由 Knowledge Tools（`query_unit_data`、`query_building_data`、`query_research_data`、`query_prerequisite_path`、`query_race_data`）从 Catalog 读取，不再写入固定系统提示词。耗时是单项开始后到就绪的近似游戏秒，不含排队、资源等待和工人行走。

Agent 只提交规范化 Tool Call。Read / Knowledge 立即查询；Action Tools 进入本轮批次，最后以 `advance(seconds)` 提交。

### 生产与取消

重复 `build/train` 会追加；省略旧需求不取消。按接受顺序调度，不自动补前提或重排阵容；兼容产能可并行，不要求前一项完成后才执行下一项。

建筑选址同时避开本帧已提交的建造命令和工人正在执行的建造目标范围，人族生产建筑保留附属建筑位置。默认位置和备用网格位置都校验主楼及挂件落点，后续建造也避开已有地面生产建筑的挂件区域。这里使用实际命令和建筑，不额外保存长期占位；工人订单消失后，相应位置重新可选。选址检查仍以当前原生合法性为准，工人后续到达前发生的拥堵或战斗变化可能需要重试。

命令完成边界：建造或建筑形态转换实际开始、训练达到请求的最少单位、研究进入游戏队列、基地形态转换出现原生订单或目标形态。技能等待对应效果、buff 或新实体等观测确认；客户端排入发送队列不算施放成功。建筑就绪和科技生效继续看观测。

已进入队列的研究若随后消失且升级未完成，Research 显示 `interrupted`。平台不自动重启；模型可在设施恢复后重新请求，也可先提交请求等待前置条件。

`cancel(target_action=..., target=..., count=...)` 用于主动调整跨轮次维护的任务队列。提供 `count` 时，从最新加入的匹配请求开始撤销，直到达到指定数量或没有更多可撤销工作；省略 `count` 时撤销全部匹配的未启动工作。已派工人、施工、已付费或已完成的训练、折跃、融合、变异和研究不取消，也不退款。工具结果会立即给出实际撤销量、剩余未启动数量和保留的已开始或已付费数量；调用 `advance` 后修改才正式提交。观测的 `Cancellable` 显示当前可撤销数量，未知不猜。

### 军队与侦察

军队目标使用观测里的 Zone。`dispatch_group` 从指定来源拆出兵力并建立新编队；`attack_group` 和 `defend_group` 只对已有外派编队改令。`reinforce_group` 可以从 `group_0` 或任意可转移的活动编队向另一编队增援，也可以把部分成员送回 `group_0`。兵力不足时整项拒绝，不部分派遣。

清图使用 `attack_group(group="group_1", mode="clear")`，也可通过 `dispatch_group(source="group_0", units={...}, order="attack", mode="clear")` 直接分兵清图。编队优先攻击当前可见且能攻击的敌方建筑，再检查已见建筑的最后位置，随后共同巡查扩张点周边和公开地图上的固定网格点。接敌时沿用战斗微操，交战结束后继续搜索；不会在一个目标清空后自动改为驻守，也不自动增援、生产或施放扫描。搜索只读取己方视野及已见历史。

`search` 报告当前目标类别与坐标、本轮已检查点数、巡查轮数及攻击能力或可达性障碍；这些是搜索进展，不代表地图已经清空。巡查一轮后可继续复查，直到模型改令、撤回、编队阵亡或对局结束。重复清图指令保留进度；普通进攻、防守或撤回指令替换清图。现有增援、分兵、合并、运输及撤回流程继续适用。`scout` 仍是单工人的一次路线侦察，不控制清图编队。

`merge_groups(destination=..., sources=[...])` 显式整合已有外出编队。所有参与编队会先统一校验；任意 ID 不存在、重复、正在撤退或召回时整项拒绝。合并完成后，source 编队以 `merged_into:<destination>` 结束，成员不会中途释放到 `group_0`。

`group_0` 是默认防守和可派兵力池：二基地完成后驻守己方 natural，二基地未完成或失守时回退主基地，且不能整体改令。外出组不自动补员；新兵默认归入 `group_0`，需显式再次派遣。定点进攻组到达目标并连续确认该区域已清空后，改为驻守并留在该区域，直到新指令或 `retreat_group`。`defend_group` 持续驻守，直到改令或撤回。`retreat_group` 立刻开始回家；幸存单位到家后才并入 `group_0`，原编组随之结束。阵亡、撤回、成员转移和当前运输状态在观测显示；执行中不表示交火或成功。运输、移动和交战微操由底层处理；只有明确启用清图时才自动搜索下一地点。

己方基地附近驻守优先使用基地侧的坡上区域；其他区域在中心附近集结，同时避开未来基地的 5×5 建筑落点。驻守地面单位若占据落点，在没有本地交战时让开，架起或埋地的单位先恢复可移动形态。该规则不改变进攻目标中心。驻防单位离开防区后，不仅因仍能看见撤退中的敌人就继续远追；双方已处于武器射程内时，仍优先保留射击、走位和施法。

同一帧内多个气矿建造请求会避开已有原生气矿及本帧已提交建造的气泉，分别选择可用位置；不额外创建请求或改变模型选择的建造数量。

正在执行明确注卵或铺毯请求的女王，在没有本地接敌或可及威胁时不被远处防区征用。实际交战仍可优先接管；确已提交防守命令打断、且没有观察到施法效果时反馈 `cast_interrupted_by_combat`。未确认效果且无打断证据时保留 `cast_effect_not_observed`。己方施法目标在效果确认前被摧毁则反馈 `target_lost_before_cast_confirmation`，均不报告施法成功。

家中仅执行待命/驻守指令的单位仍可作为明确变形或合成请求的来源；出征、侦察、运输及实际交战中的来源不被抢用。生产查询的 `source_available` 使用同一筛选。虫族变形采用当前客户端实际支持的能力，按源单位到目标单位的追加费用及追加人口计费；毒爆虫变形不增加人口。命令未被接受时不扣规划资源，原生拒绝后的存活来源可继续重试。

工人由共享执行层自动分配。三族使用相同规则：已建成气矿按每座最多 3 人补员，采气目标不超过可分配永久工人的一半，其余留作矿线和后续调度；建造、侦察等专用任务占用的工人及 MULE 不计入该人数。气矿数量由模型的建造请求决定。

自动维修和应急工人防守从空闲或采集工人中分配，不征用侦察、建造或保留工人，不覆盖本帧已发送的工人指令。侦察任务结束或被取消后，工人才释放回共享分配。

`scout.route` 数组按序检查选定矿区；`"all"` 请求一轮非己方扩张矿区中心巡查。仅检查中心，不保证全区可见或敌人找全；探员死亡失败，不自动替换，新侦察替换旧任务。侦察不自动改军队目标。

### 时间推进

`advance.seconds` 是必填正数。前面的动作先按顺序注册，游戏再运行指定秒数；生产、建造、移动和战斗继续执行。指定时间到达后返回最新观测；对局提前结束时立即返回终局。旧 `wait`/`any_of`/`all_of` 条件不再接受。平台不规定固定推进时长：战斗观察可用较短秒数，宏观生产可用较长秒数。

## 观测和反馈

能力计数按其实际含义显示：轨道基地的扫描/MULE、枢纽的加速和主枢纽召回列出能量满足条件的施法建筑数量，不保证目标、冷却或路径都可用。结构化观测保留历史字段 `scan_ready`、`mule_ready`、`chrono_ready`、`recall_ready`，其含义仍为上述能量资格。铺毯显示可用施法来源数量，具体落点仍由执行时的放置查询确认；成功施放继续以真实效果确认。

平台内部保留 Full Observation，Read Tools 在一个决策中读取同一份冻结快照。Runner 和 Versus 交给 `AgentInput.observation` 的是结构化 Brief Observation；`LLMAdapter.render_input` 将它渲染为 `[Game]`、`[Economy]`、`[Production]`、`[Infrastructure]`、`[Available Targets]`、`[Army]`、`[Relevant Zones]`、`[Abilities]` 和 `[Changes]`。Brief 仍保留普通决策所需的资源、收入、饱和度、供给、持续生产任务、建筑规模和每个活动 Group 的实际兵力，但不展开完整地图拓扑、生产槽位和低频编队诊断。相同 action、target、状态和阻塞原因的持久生产请求在 Brief 中合并显示总请求数、剩余量、付费量、可取消量和阻塞分类，最早一项的位置保留其优先级；`query_production_state` 仍返回未合并的完整顺序。Army 同时显示外派编队数量；每个外派编队显示当前命令持续的游戏时间，进攻完成后的驻扎显示驻扎时间。

Brief 的时间显示为当前时间/时限，不重复剩余时间；事件时间使用分:秒。研究的等待原因已在 Production 表达时，Infrastructure 不重复该等待状态，仍保留研究中、完成、中断及未被任务清单覆盖的状态。结构化观测和记录保留原始数值与完整研究状态。

Read Tools 包括 `query_map_overview`、`query_zone_state`、`query_route`、`query_production_state` 和 `query_army_state`。前两类动态详情查询可按生产动作/目标或 Group ID 过滤。所有查询结果都标明 `as_of_game_time`，不会推进游戏、执行侦察或获得战争迷雾中的隐藏信息。Knowledge Tools 继续提供静态单位、建筑、升级和前置关系。

| 内容 | 关注信息 |
| --- | --- |
| 游戏和经济 | 游戏时间、种族、时限、资源、供给、实际矿物/瓦斯/其他工人分配、矿物与瓦斯工人饱和值、每分钟收入 |
| 地图和基地 | Zone、角色、已知归属、矿气剩余/可靠容量、中心视野和地形关系 |
| 生产 | 实际建筑/训练/研究、设施和槽位、持久任务优先级摘要、出生进度、付费队列及阻塞 |
| 军队 | 总兵力和可派兵力、编队、成员损失、目标、执行及运输状态 |
| 侦察和能力 | 路线、路点、探员状态、本族能量与施法条件、近期事件 |

未知用 `null/unknown/?`，不替换成零；当前可见敌情和带时间的历史记忆分开。中心可见不等于全区看清，当前没有敌人不等于永久清空。对局未结束时，隐藏基地仍可能存在，平台不泄露位置或自动清图。

反馈解释上次提交是否接受、追加、无变化或拒绝；当前执行进度以观测为准。近期事件可能跨轮重复，不按展示次数统计产出或成功。

本轮 Feedback 保留从提交到返回期间产生的全部事件，不受近期历史摘要的 16 条缓存限制；LLM 的 Changes 展示其中的执行变化，提交接受仍由回执呈现。进入下一轮后清空本轮事件缓冲，存档恢复时一并恢复，避免密集生产期间漏掉较早的失败或完成通知。

一个 ToolTurn 独立持有其冻结观测，Read/Knowledge 返回值也是独立副本。外部 Agent 修改查询返回值或原始参数对象，不会改写该轮快照、已暂存动作或提交记录。参数容器非法时返回 rejected，并保留该轮此前合法暂存的动作。

神族合体和虫族战斗单位变形使用 group_0 中可用的源单位；已分配给出征编队的单位不可被后台变形任务取用。对应限制在 train 工具说明中提供。

执政官消耗两个圣堂，可为两个高阶圣堂、两个黑暗圣堂或混合组合。存在多种合法来源时，知识查询使用 source_options 和 source_count 描述消耗条件，produced_at 保留主来源名称；文本结果显示完整来源。兵力预留、OBS 可用兵力和 Fake 后端使用相同来源组合，不再把高阶圣堂视为执政官的必需科技前置。查询的 controllable/knowledge_only 状态以当前可执行目录为准，非直接训练的观察实体仍为 observable_only。

取消未开始的变形或合体任务，会在本轮暂存状态中释放相应源单位，可接着提交出征，无需额外 advance。冻结查询仍描述本轮原始快照；动作回执描述暂存后的影响。已开始变形、已出征、装载或有其他占用的单位不会因取消而被释放。

## 控制边界

Agent 负责生产、供给、科技、基地形态转换、侦察，以及本族的扫描、MULE、时空增压、注卵、菌毯肿瘤和军队宏观行动。底层负责选址、工人分配、采矿、维修、续建、集结、局部战斗和运输。自动补给、自动基地形态转换、自动 MULE、自动时空增压、自动注卵和自动种瘤都关闭。

统一 Tool 接口逐次校验：Action 会在冻结状态上预演当前事务，立即返回 staged、rejected 或 no-op，以及相关的待办数量、兵力缺口或取消数量。被拒绝和 no-op 的调用不进入 staged actions，之前已暂存的调用仍保留；Agent 可以根据结果修正，最终由 `advance` 原子提交并推进游戏。执行期间发生的开始、阻塞、完成和失败在下一 Observation 的 Changes 中返回。直接调用 `Environment.step()` 并传入旧式动作数组时，数组 Schema 非法则整批不提交。旧任务保留；默认阻塞模式暂停，连续模式仍可能推进或结束。超时为 `Tie/time_limit`，Agent 中断和故障不伪装成游戏败局。

生产类回执附带 `production_tasks`，按任务顺序列出本轮暂存变化后的未完成建造、训练、研究和基地升级任务。`submission=staged` 表示本轮新增、尚未提交；`committed` 表示此前已提交，执行状态与已知阻塞沿用当前冻结帧。取消、拒绝和 no-op 后也返回对应清单。

`production_in_progress` 单独列出当前原生建造、训练与研究。建造请求开始后会退出请求清单，但未完工建筑仍出现在这里；两份清单表示请求进度与实际施工，不应相加计算产量。未采集到的状态显示 `unknown`，已确认的空清单显示 `none`；研究状态字典只把值为真的条目列为进行中。暂存回执的 `awaiting advance` 表示等待提交，实际开工仍取决于资源、前置和产能。

战斗类回执附带 `combat_state`：`before` / `after` 只列受影响编队，包含指令、目标、撤退方式及待合并/转移信息；`home_available` 是本轮暂存后家中仍可调配的兵力。`observed_units` 是当前帧观测，`allocated_units` 是在该帧兵力上应用本轮分配变化后的数量，不表示已经到达或已经交战。合并保持 pending，撤退到达前不将兵力加回家中。所有这些回执来自隔离的任务预演，不推进游戏，也不改变已提交任务；完整查询继续读取冻结帧。


基地附近的待命与防守使用同一片连通地形上的出入口信息，优先选朝向敌方的相关入口之间的开阔位置，整队集中驻扎。没有己方基地的区域使用区域中心附近的可行走位置；扩张计划本身不算已有基地。无交战时，基地驻防坦克先抵达驻扎区域再架起；途中接敌则优先执行战斗微操。

`group_0` 的防守目标报告集结执行器实际选用的主矿或已完工二矿，不按驻点距哪个矿区中心最近来推断。工人建造指令消失且尚未施工时，请求恢复为未开始、可取消；不沿用旧的赶路状态。扩张选点受已知敌军阻挡或没有可用矿点时，反馈给出对应原因，受阻请求保留且不占用后续可执行工作的软预算。

可用目标按已完成科技及生产设施列出，并使用当前游戏版本可执行目录过滤研究项；例如 4.10 不显示仅在较新版本中可研究的 `interference_matrix`。轨道指挥部和行星要塞保留指挥中心的科技与 SCV 生产资格；虫族升级建筑与折跃门同样保留相应前置资格。建筑形态转换仍要求实际存在的原始建筑，不把后继形态当作可再次转换的来源；平台不支持执行的目标不出现在可用列表中。

`query_production_state` 还返回当前生产设施的可用槽位和实际正在施工、训练、研究的工作。按目标过滤时保留相关生产设施、科技挂件的宿主及实际形态；例如 SCV 查询包含轨道指挥部，变异单位查询包含其来源单位。未采集的信息保持未知。原生可排队位置不作为可立即并行生产的槽位展示。

资源不足时，未付费请求可按提交顺序保留资源优先级，但不预占人口；人口已满、缺前置、生产设施忙或没有可用建造位置的请求不扣留其他资源。后续明确提交的补给或基础设施仍可执行。平台不因此自动建造补给或调整生产优先级。神族防御建筑缺供能时等待并报告原因，不自动补水晶塔。

建造指令收到原生位置或路径拒绝时，执行器清除对应的无效工人建造订单，短暂避开被拒位置并重新选址；不会把发出指令当作实际开工。地图摘要的视野仅表示区域中心；敌情历史另列最早保留目击的时间，中心可见时仍保留未重新确认的区域边缘敌情。

军队详情按编队过滤时，外派编队总数仍是全局数量；明细只列所选编队，并保留底层报告的活动阶段 `phase`。编队数据未知时，总数和清单显示未知，不视为零支编队。不可调配兵力可能用于外派、变异、驻防或其他占用，因此不统一标成已外派。位置只报告实际观测的最近区域，未知时不拿命令目标代替。生产查询会明确列出未知目标；按基地对象 ID 查询时保留相关基地形态和已观测的升级施工。建筑形态转换的知识查询把人口供给标为完成后形态的供给量，与新建建筑的新增供给区分。

驻扎以一片共同区域为目标，进入该区域后不反复移向精确中心。等待指令保留原意，射程内的就地开火不因敌人位于驻防边界另一侧而改成移动。坦克可在驻扎区域直接架起；正在交战的坦克不因尚未抵达驻点而强制收起，架起/收起进行中不重复或插入移动指令。明确撤退和无交战时的驻地迁移仍正常执行。引擎回调异常记录为 backend_error，不作为普通对局败局。

引擎明确返回坦克架起到达失败时，底层检查附近可走空间与占位，短距离移开后再尝试，避免持续在同一位置失败；不收起已经部署的坦克，不覆盖新的攻击或移动指令，也不占用保留的基地落点。雷神、维京、恶火和观察者已有原生变形订单时，等订单完成再接收后续指令。

单位自身或相距不超过 7 的同编队友军视野内出现可见敌人时，底层战斗微操优先于驻扎边界、集结和赶往驻点，保留攻击、接近、走位和技能指令。远处侦察单位的视野不触发全军出动，历史与快照敌情不触发接敌。敌情消失后恢复原驻扎任务。新兵以攻击移动集结，不能攻击的支援单位仍移动跟随；集结途中接敌立即接入微操。坦克近身遭遇地面敌人时优先处理交战，不被驻点规则强制切换形态。

友军提供视野时，自己视距之外、实际武器射程内的可见目标同样属于接敌；例如坦克已能射击的目标不会因超过自身视距而触发回驻点或收起。

`attack` 的任务目标取所选区域中心；己方基地坡上驻点只在防守/驻扎时选用。底层实时敌群中心和近敌微操排除历史单位、快照与不可见单位，避免在失去观测的旧敌情位置持续聚拢。历史敌情仍保留在观测和查询中。

折跃使用当前实际可用的对应技能，先检查资源、原生放置结果和地面单位空间，并避开本帧已选择的折跃位置。扩张发生合法位置偏移时，工人按基地所属区域选择矿脉，不向基地本身发送采集指令。

扩张任务按实际基地数量计算执行目标，包含已升级的基地，不因矿脉枯竭而减少；新基地施工另按进行中建造计算。远离驻点的个别守军仍可处理自身接敌，但其远处敌情不作为家中整队的共同集结目标。附件建造空间受阻使用现有建造位置阻塞反馈。监视模式观察者和相位模式棱镜需先恢复移动形态，再接收移动指令。

生产中数量包含幼虫孵化订单、变异茧和未完成单位实体，孵化批次按实际产出数量统计；这些单位不加入完成库存或战斗控制。现存幼虫在基地损失后仍可按真实科技、资源与人口条件孵化；Queen 训练继续要求基地。MULE 只分配矿物工作。医疗运输机保留有效治疗，同一时刻为不同运输机分配不同伤员；虫后输血排除未完成目标。施工位置因近期拒绝而临时回避时，反馈说明重试，不将其一概解释成无合法放置点。
